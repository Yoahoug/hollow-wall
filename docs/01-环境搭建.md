# 环境搭建

**Hollow** —— 校园匿名留言墙。

JSP + Servlet + Service + DAO + JavaBean 的传统 JavaWeb 应用，跑在 Tomcat 9 上。
本文说明如何在本机把它跑起来。

环境不统一会浪费大量时间在排查上，因此版本按本文固定，不要自行更换。

---

## 1. 版本

| 软件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17 | 装 21 也可以，编译目标固定为 17 |
| Tomcat | **9.0.x** | 不能用 10/11：包名从 `javax.servlet` 改为 `jakarta.servlet`，代码与常见示例都不兼容 |
| MySQL | 8.0 / 8.4 | 与驱动版本对应 |
| Maven | 3.8+ | 用于打 war |
| 浏览器 | Chrome / Edge | |

自检：

```bash
java -version
mvn -v
```

两条都能输出版本号再继续。

### Tomcat 9

1. 下载 `apache-tomcat-9.0.xx.zip`（Windows）或 `.tar.gz`（macOS / Linux）
2. 解压到不含中文、不含空格的路径，例如 `D:\dev\tomcat9` 或 `~/dev/tomcat9`
3. 下文用 `$TOMCAT` 指代该路径

路径含中文会导致 JSP 找不到、日志乱码，是最常见的启动失败原因。

统一使用外置 Tomcat + war 包，不使用 IDE 内置的 Tomcat 配置，
这样每个人的运行方式一致，出问题也只在同一处。

## 2. 数据库

项目使用一个共享的 MySQL 库，连接信息由仓库维护者单独提供。

拿到连接信息后：

1. 用任意 MySQL 客户端测试连接
2. 确认能看到 `hollow_wall` 库和其中的表
3. **只读不改**：不要手工改表结构、不要删表、不要改字段

建库与初始化脚本由仓库维护者编写并执行，其他人不需要执行任何 `CREATE` / `ALTER`。
表结构的唯一来源是仓库中的 SQL 脚本。结构需要调整时，由维护者修改脚本后统一执行，
不要在数据库里直接改——直接改的字段不会出现在脚本中，其他人重新建库就是错的。

### JDBC 连接串的四个参数

```properties
jdbc.url=jdbc:mysql://<host>:<port>/<database>?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
jdbc.user=<user>
jdbc.password=<password>
```

| 参数 | 缺失时的现象 |
| --- | --- |
| `allowPublicKeyRetrieval=true` | 报 `Public Key Retrieval is not allowed`，MySQL 8 默认认证方式下必现 |
| `serverTimezone=Asia/Shanghai` | 时间差 8 小时 |
| `characterEncoding=utf8` | 中文乱码 |
| `useSSL=false` | 本地连自建库时的证书告警 |

### 本地配置

```bash
cp src/main/resources/db.properties.example src/main/resources/db.properties
# 编辑 db.properties，填入实际的 host / user / password
```

`db.properties` 在 `.gitignore` 中，**不要提交**。提交前确认 `git status` 里没有它。

## 3. 运行

```bash
git clone <repository>
cd hollow-wall

cp src/main/resources/db.properties.example src/main/resources/db.properties
# 编辑 db.properties

mvn clean package

cp target/hollow.war "$TOMCAT/webapps/"
"$TOMCAT/bin/startup.sh"        # Windows: %TOMCAT%\bin\startup.bat
```

打开 `http://127.0.0.1:8080/hollow/`

URL 中的 `hollow` 由打包产物名决定，不能省略。访问 `http://127.0.0.1:8080/`
会进入 Tomcat 首页，不是本系统。

停止：`"$TOMCAT/bin/shutdown.sh"`（Windows 用 `shutdown.bat`）。

## 4. 环境自检

以下四项全部通过后再开始写业务代码。带着坏环境写代码，
后续所有问题都分不清是自己写错还是环境问题。

- [ ] `mvn clean package` 成功，产出 war 包
- [ ] 打开首页不是 404、不是 500
- [ ] 用测试账号能登录
- [ ] 打开自己负责的页面，内容正常渲染

## 5. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Public Key Retrieval is not allowed` | 连接串缺 `allowPublicKeyRetrieval=true` | 补参数 |
| `Access denied for user` | 账号密码错误，或该账号未授权此库 | 核对连接信息 |
| `ClassNotFoundException: com.mysql.cj.jdbc.Driver` | 驱动依赖作用域写成了 `provided` | 改回默认作用域，重新打包 |
| 中文乱码 | 库/表不是 `utf8mb4`；JSP 缺 `pageEncoding="UTF-8"`；Tomcat Connector 缺 `URIEncoding="UTF-8"` | 三处都要对 |
| 打开是 404 | war 未放入、Tomcat 未重启、URL 少了 `hollow` | 逐项检查 |
| 打开是 500 | 看 `$TOMCAT/logs/catalina.out` 末尾的堆栈 | 不要猜，看日志 |
| 登录后立刻掉线 | 浏览器禁用 Cookie；代码中未取 Session | 检查 Cookie 设置 |
| 改了代码未生效 | 未重新打包，旧的解压目录仍在 | 删除 `webapps/hollow/` 后重启 |
| 8080 端口被占用 | 本机已有 Tomcat 或其他服务 | 改 `conf/server.xml` 的 Connector 端口 |
| 编译报 `程序包 javax.servlet 不存在` | 使用了 Tomcat 10+ | 换回 Tomcat 9 |

## 6. 日常工作流

```bash
# 开工
git checkout main && git pull
git checkout feat/<username>-<module>
git rebase main

# 写代码、自测

# 收工
git add <只加自己改动的文件>
git commit -m "feat(module): 做了什么"
git push
```

三条约定：

1. 只 `git add` 自己名下的文件，不要用 `git add .`
2. 提交前跑一次 `mvn clean package`
3. 提交粒度尽量小，一次提交只做一件事

环境问题统一在协作频道提出，不要自行更换 JDK、Tomcat 版本或修改 `pom.xml`。
